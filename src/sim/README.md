# 模拟内核与候选规则

`GameEngine` 是不依赖 DOM、计时器、渲染帧率的 TypeScript 模拟。调用方在游戏运行时推进整数 `step(ticks)`；暂停和切后台时不调用，恢复时不得补算墙上时间。`snapshot()` 返回隔离副本。`state` 是供渲染读取的当前状态，调用方不应直接改写。

## 接口

- `new GameEngine(map, config, seed)`：建立干净开局，克隆地图及参数。
- `dispatch(owner, sourceId, targetId, fraction=1)`：验证所有权、目标、路线和可用兵力后预定固定预算；返回是否接受和实际预算。
- `cancel(sourceId)`：取消该源尚未发出的预算；不额外返还驻军。
- `grantReward(id, owner, targetId, units)`：同一有效 ID 只发一次；无真实平台广告关联。UI 必须说明演示奖励来源。
- `setPlayerAI(enabled)`：启停玩家方自动研究策略，操作进入回放。
- `exportReplay()` / `GameEngine.fromReplay(map,replay)`：包含版本、地图/配置哈希、seed、外部命令及终止 tick；复现至终止 tick。AI 由相同配置和 seed 重算，避免重复执行 AI 指令。
- `assertInvariants()`：核对每个源的预留总额、整数非负兵力及全局守恒。

阵营支持 `neutral/blue/brown/magenta/green/red`。图形、多边形、覆盖圈与加兵图标可以在地图中存在，不会因此暗中产生炮塔伤害或收益。

## 数值证据状态

`DEFAULT_CONFIG` 保留交接文档中的工程候选：生产 5/s、发射 12/s、每包 1 兵、速度 110 设计像素/s，不能理解为原游戏公式。

长录像场景与回归测试使用本轮源帧研究得到的可替换设置：

| 参数 | 场景设置 | 状态与限制 |
|---|---:|---|
| 蓝方产兵 | 13.7/s | 指定录像中的有效速率候选，未知升级和特殊效果影响 |
| 棕/紫红产兵 | 11/s | 静置数字序列测量的场景有效速率 |
| 中立恢复 | 7/s | 灰色守军受攻击间隙逐帧增兵支持；并非零生产 |
| 中立/彩色生产软上限 | 125/250 | 不削除外部增援；占领后按当前所有权切换 |
| 每次发射 | 5 兵 | 已观察到源兵数相邻帧扣 5；积分到整批才发射 |
| 发射速率 | 16/s | 5 兵一批，约 0.3125 秒；最后不满 5 的预算可发完 |
| 移动速度 | 80 设计像素/s | 原录像位置测量候选，不随屏幕分辨率改变 |
| 路线 | any-visible | 交互规则仍未最终确认；同时支持邻接和友军中继图路径 |

以上数值来自录像研究，尚未通过原游戏可控输入实验。不同视频/等级不能自动共用。证据原帧、测量区间和细节由项目的 `references` 研究文档维护。

## 核心结算规则

1. `reserved` 是 `garrison` 的子集。预定不扣兵，发射时同时扣驻军和预留。多个队列共用一个源的发射额度，以提交顺序消耗，重复下令不能提高吞吐率。
2. 每包独立移动、按折线弧长行进；到达按 `arrivalTick → subTick → sequenceId` 排序。整数 tick 末抵达的包排在该 tick 更早的小数抵达之后，不按玩家阵营优先。
3. 同阵营抵达增援；异阵营按 1:1 相消，双方消耗记入伤亡。攻击大于守军则易主并留下差额；相等时保留防守者所有权且驻军为零。这是明确候选规则。
4. 源受攻击时，守军损失可能消耗预留兵；优先缩减最新未发预算。易主时取消剩余队列。在途包保留出发时阵营，抵达时查看目标当时所有权。
5. 自然生产使用整数定点余数，达到软上限时清零余数；增援和奖励可以超过软上限，不会被下一 tick 截断。
6. 失去所有地块但仍有在途兵的阵营仍存活。只剩一个有色阵营时结算一次；默认不要求吞掉全部中立区。单阵营地图作为研究沙盒不自动结束。
7. 每个 tick 的兵力满足：`驻军 + 在途 = 初始 + 累计生产 + 奖励 − 双方伤亡`。预留不重复计入总量。

## AI 与测试边界

AI 使用实际驻军、队列、在途兵、路径时长及目标生产估计目标预算，协调多个源的兵流持续时长；无法进攻时可以用真实驻军向前线增援。无隐藏兵力、增产、瞬移或强制获胜。它是本实现的研究策略，尚未复现原游戏的完整决策行为。

`npx vitest run tests/sim.test.ts --disableConsoleIntercept` 覆盖 26 个用例：预留/取消、源被占领、在途存活、批量发射、距离和弯路、连续扣兵、平局、同时到达、自然/中立生产、软上限、奖励去重、完整回放、30/60/120 渲染调度一致性，以及 4 个 seed 的完整 AI 对局。AI 测试逐 tick 检查守恒，并设 600 游戏秒上限；通过它不能推导真人首胜率或原录像时间匹配率。
